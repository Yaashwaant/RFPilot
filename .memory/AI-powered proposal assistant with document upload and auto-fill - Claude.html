Yes, the UI and the fill-at-cursor step are both possible

What you describe is a guided “pick target, pick question, fill” flow on top of a document viewer. The only real question is how exactly you can capture the cursor and write back, and that differs by file type and viewer.

Feasibility by file type

FormatCapture cursorWrite answerDifficulty
ExcelExact cell (Sheet1!C14)Set cell valueEasy
WordParagraph or table cellInsert text thereMedium
PPTSlide plus text boxFill that shapeMedium-hard
PDFx/y position on a pageOverlay text onlyHard (no true editing)

How the box works, two ways

1. Embedded editor (ONLYOFFICE or Collabora)

  • The document looks exactly like the original because it is the real editor.
  • Your “Add Answer” button sits in your own React UI, floating top-right over the box.
  • The editor runs in an iframe, so your app talks to it through its connector or plugin API. It asks “where is the cursor or selection?” and later says “insert this text here.”
  • Excel, Word and PPT all work the same way from your side, which makes this the only approach that gives true “exactly as it is” fidelity for all three.

2. Custom viewer plus a backend that edits the file

  • Excel: Univer gives a near-perfect view, and a click gives the exact cell.
  • Word: docx-preview renders well, but you must tag each paragraph with an index so a click maps to the file.
  • PPT: browser renderers are weak. The better trick is to convert slides to images with LibreOffice and overlay invisible clickable regions for each shape.
  • The backend writes with openpyxl, python-docx and python-pptx, then re-renders.
  • This gives full UI freedom, but “exactly as it is” is not guaranteed for Word or PPT.

The UI state machine

IDLE → click "Add Answer"
  → PICK_TARGET   (banner: "Click where the answer should go")
  → PICK_QUESTION (banner: "Now select the question", Go disabled)
  → READY         (question chip shown, Go enabled)
  → GENERATING    (streaming, shimmer at target location)
  → REVIEW        (answer inserted, highlighted, Accept / Regenerate / Undo)
  → IDLE

Two details matter here:

  • You can skip the separate target step if the user’s cursor is already placed when they click Add Answer, which matches what you described. Store the cursor as an anchor the moment the button is pressed, because clicking the button may make the document lose focus.
  • Highlight the filled answer as an “AI draft” until the user accepts it, so they can see and undo what changed.

Things that will bite you

  • Focus loss: clicking your external button can clear the selection in the editor. Save the anchor on mousedown, before focus moves.
  • Excel merged cells: the answer must go in the top-left cell of the merge.
  • Word tables: a question in one cell with the answer in the next cell is common, so offer “answer goes in the adjacent cell” as a smart default.
  • PPT overflow: long answers will spill out of a text box, so you need auto-shrink or a warning.
  • Formatting: inherit the font and style of the target spot rather than inserting plain text.
  • Download: with the embedded editor this is trivial and the original formatting is kept. With the custom approach you download the file your backend patched.

My recommendation

If “see the document exactly as it is” and “fill at the cursor” are your top priorities, use ONLYOFFICE embedded in Next.js, wrapped with your own shadcn/ui chrome. Build the state machine above in Zustand, with Framer Motion for the banners and toasts. That gets you a working demo for Excel and Word fastest. Do PPT and PDF afterwards.
